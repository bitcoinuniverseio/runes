Runes Learning Academy

Track 6: Build a Wallet or Application Integration

Integrate @bitcoinuniverse/runes-tools, manage cardinal inputs, build safe review screens, and prevent balance destruction.

← Back to All Academy Tracks
Audience: Wallet architects, frontend engineers, and Bitcoin backend developers. · Duration: ~30 minutes
Learning Outcomes

Prerequisites: TypeScript/JavaScript and Bitcoin transaction serialization experience.

Outcomes: Integrate @bitcoinuniverse/runes-tools, manage cardinal inputs, build safe review screens, and prevent balance destruction.

Curriculum Lessons

1. Rune Outpoint Inventory

Track UTXO rune balances separately to avoid spending rune UTXOs as fee inputs.

Controlling Rules: R44

2. Runestone Assembly Pipeline

Encode edicts, sort by RuneId, calculate minimal varints, and assemble scriptPubKey.

Controlling Rules: R4, R34

3. Pre-Signing Validation Gate

Decode built runestones locally before requesting signatures.

Controlling Rules: R17, R45

4. Avoiding Blind Signing

Surface exact rune amounts, change destination, and burn warnings to users.

Controlling Rules: R38, R41

Track Knowledge Assessment

Answer the questions below to test your understanding of this track's consensus invariants.

Question 1: Why must a wallet maintain a separate rune outpoint inventory?

Protocol Explanation

Rune-unaware coin selection destroys value: spending a rune-bearing UTXO as fee releases its runes into the unallocated pool where they follow output 0.
